# 画面对齐与 80 分通过标准

## 一、适用版本

适用版本：v1 规划版、网页概念演示、后续 Unity Windows x64 和 Unity macOS Universal 桌面原生版。

## 二、视觉获取与对标方法

对标目标不是复制现有游戏，而是拆解它们解决问题的方法，再转化为本项目统一风格。

1. 资料获取：优先使用官方页面、官方截图、官方博客和商店页；不把非授权素材放入项目。
2. Chrome MCP 审核：打开本地 `index.html`，检查首屏是否能清楚识别木屋、森林、河流、木桥、空地游戏机、像素小游戏。
3. 画面截图审核：在桌面宽度和移动宽度各截一次图，检查主角、入口、目标提示和 HUD 是否可读。
4. 玩法路径审核：按“森林拾取 -> 修桥 -> 游戏机 -> 像素贴纸 -> 出口返回”点击一轮，检查状态变化和反馈。
5. 统一性审核：确认自然生活、方块化资源、现代光效、像素模式之间有统一色彩和交互逻辑，不出现拼贴感。

## 三、参考权重

- 主要参考 1：小岛生活、家园起点、温和交互、短路径社区感。
- 主要参考 2：木屋、资源采集、方块化边界、定点微建造。
- 次要参考：远景光幕、电子屏、入口后规则变化和趣味化现代风格。

## 五、三次 Review 规则

### Review 1：资深游戏设计者

- 检查问题：核心循环是否好玩，玩家每一步是否有动机。
- 通过标准：每个节点都有目的、反馈和下一个目标。
- 不通过示例：玩家点完森林后不知道为什么要去河边；游戏机只是装饰而不是强入口。

### Review 2：资深玩家

- 检查问题：是否能看懂、是否愿意继续、是否有轻松但明确的奖励。
- 通过标准：首屏能看到目标，按钮反馈明确，失败不惩罚，完成有奖励。
- 不通过示例：贴纸收集没有变化；出口条件不清楚；返回主世界后没有新东西。

### Review 3：资深架构师

- 检查问题：设计是否能直接拆成数据、状态机、场景和接口。
- 通过标准：每个交互都能对应 `PlayerState`、`WorldNode`、`MiniGameResult` 或 Unity 组件。
- 不通过示例：只描述氛围，没有触发条件、数据变化、失败分支和存档字段。
