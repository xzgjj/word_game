# 画面对齐与 80 分通过标准



## 一、适用版本

适用版本：v1 规划版、网页概念演示、后续 Unity Windows x64 和 Unity macOS Universal 桌面原生版。



## 二、视觉获取与对标方法

对标目标不是复制现有游戏，而是拆解它们解决问题的方法，再转化为本项目统一风格。

1. 资料获取：优先使用官方页面、官方截图、官方博客和商店页；不把非授权素材放入项目。
2. Chrome MCP 审核：打开本地 `index.html`，检查首屏是否能清楚识别木屋、森林、河流、木桥、空地游戏机、像素小游戏。
3. 画面截图审核：在桌面宽度和移动宽度各截一次图，检查主角、入口、目标提示和 HUD 是否可读。
4. 玩法路径审核：按“森林拾取 -> 修桥 -> 游戏机 -> 像素贴纸 -> 出口返回”点击一轮，检查状态变化和反馈。
5. 统一性审核：确认自然生活、方块化资源、现代光效、像素模式之间有统一色彩和交互逻辑，不出现拼贴感。
6. 素材审核：AI 生成素材需要保存提示词、用途和版本；开源素材需要保存来源链接、许可证和作者信息；未确认授权的素材不得进入仓库。



## 三、参考权重

- 主要参考 1：小岛生活、家园起点、温和交互、短路径社区感。
- 主要参考 2：木屋、资源采集、方块化边界、定点微建造。
- 次要参考：远景光幕、电子屏、入口后规则变化和趣味化现代风格。



## 三点一、对标拆解要求

对标不是“像某个游戏的截图”，而是把优秀项目解决设计问题的方法转化为《星绪森林》的规则、画面和实现标准。

| 对标对象 | 必须学习的方法 | 本项目的落地标准 | 不允许的偏差 |
| --- | --- | --- | --- |
| 动物森友会 | 家园起点、轻松生活动机、玩家主动布置、非强制引导 | 木屋是安全起点，木牌像小镇公告而不是任务面板，玩家在单主地图里摆放建设元素 | 做成跑腿任务列表、强箭头引导、多个割裂主世界地图 |
| 我的世界 | 材料来源清楚、采集到建设的因果链、放置反馈强 | 木材/石子/花种/河贝/鱼来自可理解地点，材料进入物品栏后立刻影响兑换和建设可用性，建设物落位可见 | 材料凭空奖励、建设只是菜单数值、资源没有用途 |
| 崩坏：星穹铁道 | 现代电子入口、远景光幕、进入后规则变化 | 空地游戏机、旧卡带、远景光幕和像素模式转场建立“进入另一套规则”的感觉 | 引入战斗、抽卡、大剧情压过家园玩法，或让现代光效抢走木屋核心 |

每次做玩法、UI、画面和实现时，都要能说清楚：这个设计点对标的是哪种方法，为什么适合《星绪森林》，玩家会看到什么反馈，状态会怎么变化。



## 四、80 分通过评分表

总分 100 分，80 分以上才允许进入实现阶段。

| 维度 | 分值 | 通过要求 |
| --- | --- | --- |
| 场景可读性 | 20 | 一眼能分辨木屋、森林、河流、桥、空地游戏机和像素小游戏 |
| 玩法闭环 | 20 | 拾取、修桥、进入、收集、返回均有可见状态反馈 |
| 视觉统一 | 15 | 自然、方块资源、现代光效和像素模式统一在同一色彩系统内 |
| 桌面原生可实现性 | 15 | 每个画面元素都能映射为 Unity 场景节点、脚本或 UI 组件 |
| 情绪主角表现 | 10 | 欢笑、安静、激动有清晰外观和能力差异 |
| UI 信息密度 | 10 | HUD 只显示当前位置、目标、资源和当前情绪，不压迫画面 |
| 新手路径 | 10 | 新玩家不读长说明也能在 5 分钟内完成第一轮闭环 |
| 素材合规 | 必选 | AI 生成或开源素材来源可追溯，未授权素材不得使用 |

附加硬门禁：

- 动森式体验门禁：木牌、物品栏和建设界面必须像小镇生活工具，不得变成任务列表或后台管理界面。
- 我的世界式反馈门禁：每种基础材料必须有来源、用途、数量变化和建设/兑换反馈。
- 星穹铁道式入口门禁：游戏机和远景光幕必须表现现代电子感和规则切换，但不得喧宾夺主。
- 网页顺序门禁：网页概念演示放在 Unity 核心系统和视觉方向稳定之后更新，不得反向主导 Unity 实现。



## 五、三次 Review 规则



### Review 1：资深游戏设计者

- 检查问题：核心循环是否好玩，玩家每一步是否有动机。
- 通过标准：每个节点都有目的、反馈和下一个目标。
- 对标检查：动森的家园生活动机是否成立；我的世界的材料到建设因果链是否成立；星穹铁道的游戏机入口是否只是规则切换入口而不是战斗/剧情扩张。
- 不通过示例：玩家点完森林后不知道为什么要去河边；游戏机只是装饰而不是强入口。



### Review 2：资深玩家

- 检查问题：是否能看懂、是否愿意继续、是否有轻松但明确的奖励。
- 通过标准：首屏能看到目标，按钮反馈明确，失败不惩罚，完成有奖励。
- 对标检查：玩家是否能自然理解“采集 -> 兑换 -> 建设 -> 游戏机 -> 回家展示”；UI 是否像家园工具和小镇记录；资源、建设、贴纸墙是否都有即时反馈。
- 不通过示例：贴纸收集没有变化；出口条件不清楚；返回主世界后没有新东西。



### Review 3：资深架构师

- 检查问题：设计是否能直接拆成数据、状态机、场景和接口。
- 通过标准：每个交互都能对应 `PlayerState`、`WorldNode`、`MiniGameResult` 或 Unity 组件。
- 对标检查：单主地图布置能力、材料建设反馈、电子入口规则切换是否都有服务、状态、测试和存档字段支撑。
- 不通过示例：只描述氛围，没有触发条件、数据变化、失败分支和存档字段。



## 五点一、每 10 分钟 Review 清单

每 10 分钟或每完成一个小功能后必须做一次快速 review，并把偏离点写入 `notes.txt` 或 `diff.md`。

1. PRD 对标：当前实现是否仍服务“单主地图家园冒险”，有没有把网页或临时脚本当成最终方向。
2. 动森对标：木屋、木牌、建设和小镇记录是否仍然温和、生活化、非强制。
3. 我的世界对标：资源是否有地点、用途、数量变化和放置反馈。
4. 星穹铁道对标：游戏机、旧卡带、远景光幕和像素模式是否清楚表达“进入后规则变化”。
5. UI 对标：物品栏、木牌兑换、建设界面是否能让玩家自然理解下一步，不像任务清单或后台表格。
6. 技术对标：本次功能是否有状态字段、接口、失败分支、最小测试和存档落点。
7. 画面门禁：最终画面是否朝 80 分以上推进，而不是只满足“能跑”。
8. 网页顺序：Unity 核心系统和画面方向未稳定前，不更新网页概念演示。
