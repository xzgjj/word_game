# 星绪森林视觉可玩版美术方向与资产清单

## 目标口径

这份文档用于阶段 8：Unity 视觉可玩版。目标是把已经跑通的 Unity 核心闭环升级成“主角、家园、资源、建设、游戏机、贴纸墙都能一眼看懂”的可玩画面。

本阶段仍然遵守：

- Unity 桌面原生版优先，网页演示不反向主导 Unity。
- 单主地图家园冒险，不扩成多个主世界地图。
- 参考游戏只学习方法，不复制画面、角色、UI、资产或布局。
- 不加入战斗、抽卡、账号、联网、商业化系统。

## 主角必须保留的元素

必须保留：

- 长黑发和偏安静、神秘、温柔的气质。
- 紫黑主色与少量珊瑚/羽饰/贝壳感点缀。
- 漂浮灵鱼或水光小精灵，作为情绪能力和河流世界观的视觉锚点。
- 三个表情状态：安静、欢笑、激动。
- 主角与森林/河岸/星屑灯芯/动态表情系统之间的关联。

需要弱化：

- 过强的战斗角色感、华丽大披风占屏、过尖锐的暗黑轮廓。
- 过多裸露和复杂蕾丝细节，避免和温和家园冒险气质冲突。
- 过强紫色主导，防止整个游戏变成单一紫蓝调。

## 主角玩法功能映射

| 表情状态 | 画面表现 | 玩法用途 | Unity 首版实现 |
| --- | --- | --- | --- |
| 安静 Quiet | 眼神收敛，灵鱼低速环绕，浅蓝水光 | 漂浮、慢速观察、靠近提示更清晰 | 表情头像 + 主角脚下轻水纹 |
| 欢笑 Laughing | 笑眼，披肩/发梢轻微上扬，暖色粒子 | 冲刺、采集反馈更活泼 | 表情头像 + 短距离速度反馈 |
| 激动 Excited | 眼睛放大，灵鱼跃起，星屑闪烁 | 高跳、小游戏贴纸收集反馈 | 表情头像 + 星屑跳跃粒子 |

阶段 8 不做完整角色动作系统。建议先使用一个“主角可读代理体”：

- 世界中：低模小人或竖版 Sprite/Card，颜色和轮廓接近概念图。
- UI 中：使用概念图裁切/重绘后的三表情头像。
- 后续阶段：再替换为 3D 模型、骨骼动画或 Live2D/Spine 等方案；当前不新增技术栈。

## 世界和地图方向

用户确认方向：参考动森和星露谷的引导与生活感，但整体更写实、更高清。

本项目落地解释：

- 不是照片级写实；首版采用 Unity URP 的高清低模/半写实手绘材质。
- 比动森更细一点：树叶、木屋、河岸、贝壳、石头要有材质层次。
- 比星露谷更立体：用 3D 单主地图、真实光照、昼夜色温和可走空间。
- 保留温和、清楚、家园感，不做高压战斗场景。

推荐镜头：

- 主世界：45 度左右俯视/斜俯视镜头，优先正交或轻透视，保证家园布置可读。
- 小游戏：像素平台视角，规则和主世界明显切换。
- 不建议阶段 8 做肩后第三人称，因为会放大角色动画、碰撞、相机遮挡和场景细节成本。

## 单主地图构图

1080p 截图中必须同时读出这些空间关系：

```text
左侧/左上：木屋与贴纸墙
木屋前：木牌
一侧：旁友森林、树枝、花种
中部/下方：河岸、河水、石子、河贝、鱼影
河上：半损坏桥 / 已修复桥
另一侧空地：游戏机和游戏机底座
远景边界：不可到达现代光幕
木屋周围：花圃、林间路牌、河岸灯、自建小屋空位
```

动森方法用于“家园锚点和生活化入口”；星露谷方法用于“家门口到资源区的短距离劳动闭环”；Minecraft 方法用于“材料到建设物的因果反馈”；星穹铁道方法用于“电子入口和进入后规则变化”。

## 资产清单

### 主角资产

| 资产 | 第一轮形态 | 要求 |
| --- | --- | --- |
| 主角代理体 | 低模/竖版 Sprite | 轮廓要能看出黑发、紫黑服装、羽饰/贝壳点缀 |
| Quiet 头像 | UI 图 | 用于情绪切换和提示 |
| Laughing 头像 | UI 图 | 用于冲刺/欢笑状态 |
| Excited 头像 | UI 图 | 用于高跳/激动状态 |
| 灵鱼特效 | 简单半透明 Mesh 或粒子 | 主角旁轻微环绕，不能抢画面 |

### 主世界资产

| 区域 | 必要资产 | 视觉要求 |
| --- | --- | --- |
| 木屋 | HomeCabin、StickerWall | 温暖、安全、像家 |
| 木牌 | HomeSignboard | 像小镇记录工具，不像任务板 |
| 森林 | ForestTree、Branch、FlowerSeed | 材料来源清楚，颜色不糊成一片 |
| 河岸 | River、Stone、Shell、FishShadow | 河贝和鱼影可读，水体不复杂但要有高光 |
| 桥 | DamagedBridge、RepairedBridge | 修复前后差异明显 |
| 空地 | ArcadeMachine、ArcadeBase | 现代电子感，青绿色发光 |
| 远景 | DistantLightScreen | 不可到达边界，弱发光，不压过家园 |
| 建设 | FlowerBed、ForestSign、WoodFence、CraftBench、RiverLamp、CustomBuilding_1x1、CustomBuilding_2x2 | 建设成功后能替换空位并被存档 |

### UI 资产

| UI | 要求 |
| --- | --- |
| 12 格背包 | 小而清楚，格子稳定，不像网页后台表格 |
| 木牌面板 | 三块：今日可换、图纸记录、小镇记录 |
| 建设菜单 | 显示材料需求、可放置、材料不足、图纸未解锁 |
| 短提示 | 一句话生活化提示，靠近节点出现 |
| 情绪头像 | 三状态可切换，和主角概念图统一 |

## 资产生成与实现路线

### 阶段 8A：可替换低成本资产

- 用 Unity 基础几何体和 URP Lit/Emission 材质搭出木屋、树、桥、游戏机、光幕、建设物。
- 主角用竖版 Sprite/Card 或低模代理体，不做完整建模。
- 用材质、轮廓和发光效果保证 1080p 可读。

### 阶段 8B：半写实高清替换

- 为木屋、河岸、树、石头、贝壳、游戏机做统一风格模型。
- 主角重绘或生成三张表情头像，必要时做 2.5D 角色牌。
- 每个资产入库前记录来源、许可证、用途和处理方式。

### 阶段 8C：角色与场景精修

- 如果后续选择 3D 主角，再做建模、绑定、基础动画和三表情切换。
- 增加脚步、采集、建设、游戏机转场、贴纸墙更新的轻量特效。
- 保持服务层为唯一业务规则来源，画面层只响应状态。

## 验收标准

| 项目 | 分数 |
| --- | --- |
| 主角融入游戏：轮廓、颜色、三表情和灵鱼与玩法一致 | 20 |
| 单主地图可读：木屋、木牌、森林、河流、桥、游戏机、光幕关系清楚 | 20 |
| 写实高清方向成立：材质、光照、比例比纯占位明显提升，但不压迫家园感 | 15 |
| 资源到建设反馈清楚：材料来源、兑换、放置、失败提示可见 | 15 |
| UI 像生活工具：背包、木牌、小镇记录，不像任务列表 | 10 |
| 游戏机入口规则切换明显：电子感、菜单入口、像素小游戏差异 | 10 |
| 自动测试与构建通过：EditMode、PlayMode、Windows 构建和启动冒烟 | 10 |

低于 80 分：先修视觉、反馈和 UI，不新增玩法。

## 阶段 8B 二级对标要求

阶段 8A 的可操作演示不等于最终画面完成。用户补充的动森和 Minecraft 参考图已经归档到：

```text
assets/reference/visual-benchmark/
```

二级对标和更详细验收标准见：

```text
doc/visual_benchmark_review_stage8.md
```

后续实现优先级调整为：

1. 先修主角辨识度：黑发、紫黑服装、羽饰/贝壳、灵鱼、三表情进入 HUD。
2. 再修森林：树数量减少到 5-7 棵，形成森林边缘和可进入缺口，不做树墙。
3. 再修河流：分段岸线、浅滩、湿土边、水面高光、石子/河贝/鱼影分区。
4. 再修木屋和游戏机：木屋成为家园锚点，游戏机成为电子入口但不压过家。
5. 最后跑 1080p 截图 review 和自动验证。

## 当前设计结论

主角形象已经确定，可以进入 Unity 视觉可玩版。剩余设计不需要用户继续逐项补充，默认由实现者按本文件和 `doc/visual_benchmark_review_stage8.md` 补齐：主世界采用单地图家园冒险，画面取动森和星露谷的生活引导与资源循环方法，质感朝 Unity URP 半写实高清低模推进，电子入口取星穹铁道的规则切换方法但不引入战斗、抽卡和大剧情。
