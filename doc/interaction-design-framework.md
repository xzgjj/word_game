# 星绪森林交互设计框架

## 目标

这份文档把“玩家在系统里做什么、状态怎么变化、玩家看到什么反馈”写成实现标准。后续新增功能必须先补本文件里的路径、状态和反馈，再写代码。

## 对标方法

参考只取方法，不复制素材或 UI。

- 动森方向：生活入口、家园装饰、DIY/建设、温和提示。公开参考：`https://animalcrossing.nintendo.com/new-horizons/create/`
- Minecraft 方向：材料来源清楚、形状反馈强、材料改变世界。公开参考：`https://www.minecraft.net/en-us/about-minecraft`
- Unity 技术方向：阶段 8C 先用 deterministic walkable-area；阶段 9 再把边界可视化为 Collider/Trigger 或调试层。公开参考：`https://docs.unity3d.com/Manual/class-CharacterController.html`

## 交互原则

1. 不靠常驻任务文本推进。玩家靠场景缺口、物件位置、短提示和反馈理解下一步。
2. 首次遇到系统时允许一次性引导；之后必须降噪。
3. 成功必须有至少一种反馈：数字变化、物体替换、发光、音效、短提示。
4. 失败必须说明原因，并且不能错误扣材料或写入建设状态。
5. 看起来能走的地方必须能走；看起来是水体或地图外必须不能走。
6. 背包不提前暴露所有系统物品；只有基础物品和已获得物品可见。

## 主路径矩阵

| 路径 | 玩家行为 | 状态变化 | 可见/可听反馈 | 失败处理 |
| --- | --- | --- | --- | --- |
| 首次采集 | 靠近树枝/石子/花种，按 `E` | `Items[item] += amount` | 首次显示“按 E 收进背包”；成功提示；轻音效 | 未知节点提示“采集点不存在”，不改背包 |
| 打开木牌 | 靠近木牌按 `E` | `KnownSystems += signboard`，初始图纸写入 `UnlockedBlueprints` | 木牌面板显示今日可换/图纸记录/小镇记录 | 无状态时提示初始化失败 |
| 今日赠礼 | 木牌打开后按 `1` | `Wood += 1`，`SignboardDailyRewardClaimed = true` | “今日赠礼已放入背包”；木牌该项变为今日已领 | 重复领取失败，不再加物品 |
| 普通兑换 | 木牌打开后按 `2-5` | 扣成本物品，增加输出物品 | 成功提示；背包对应分类出现新物品 | 材料不足失败，不扣材料 |
| 修桥 | 靠近半损坏桥按 `E` | `PlacedBuildings += Bridge`，`BuiltCount += 1`，桥图纸进度更新 | 断桥模型隐藏，修复桥显示；成功音效 | 材料不足或图纸未解锁，不扣材料 |
| 过河 | 修桥后从桥面移动 | 无业务状态，仅位置变化 | 玩家能通过桥面；河道外仍阻挡 | 未修桥时水体禁入；桥外水体禁入 |
| 清理花圃地块 | 对花圃槽连续按 `E` | `WorldNodeStages[nodeId]` 从 0 到 3；逐步加 `Wood/Stone/FlowerSeed` | 落枝/碎石/杂草分层隐藏；地块变清理后土壤 | 背包加入失败则不推进清理阶段 |
| 建设花圃 | 清理完成后按 `E` | `PlacedBuildings += FlowerBed`，消耗花种/石子 | 花圃显示，清理槽隐藏 | 材料不足不扣材料，清理后的空地保留 |
| 背包分类 | 按 `I` 打开，按 `← / →` 切换 | `InventoryCategoryIndex` 循环变化 | 分类标题变化，轻音效；只显示基础/已获得物品 | 空分类显示“这一栏还没有发现物品” |
| 游戏机菜单 | 靠近游戏机按 `E` | `KnownSystems += arcade`，`UnlockedMiniGames += arcade-01` | 游戏机菜单显示，屏幕发光 | 没旧卡带显示未就绪 |
| 小游戏进入 | 游戏机菜单按 `Enter` | `ActiveMiniGameId = arcade-01` | 切换 `MiniGame01` 场景 | 条件不足不切场景 |
| 贴纸回收 | 收齐 3 贴纸后出口按 `E` | `StickerWallCount += 1`，完成小游戏图纸进度 | 回到主世界，贴纸墙更新 | 贴纸不足时出口提示等待光 |

## 背包信息架构

背包分类是 UI 组织方式，不改变底层 `ItemId`。一个物品可以出现在多个用途分类中，例如木材既是采集物，也是建设材料。

| 分类 | 显示规则 | 设计意图 |
| --- | --- | --- |
| 采集 | 木材、石子默认显示；河贝、鱼获得后显示 | 让玩家理解材料来自世界 |
| 交换/货币 | 表情碎片、星屑灯芯、贴纸获得后显示 | 避免开局暴露后期兑换目标 |
| 建造种植 | 花种、木材、石子默认显示 | 直接服务花圃/桥/路牌建设 |
| 室内/特殊 | 旧卡带、贴纸获得后显示 | 为游戏机和室内装饰预留 |

## 反馈层级

| 层级 | 要求 | 当前实现 | 阶段 9 升级 |
| --- | --- | --- | --- |
| 文案 | 只在靠近物件或结果发生时出现 | HUD 短提示 | Unity UI 气泡 |
| 数字 | 背包数量立即变化 | IMGUI 数字 | 图标网格数字 |
| 场景 | 建设/清理改变物体显隐 | `BuildPlacementView` / `ClearingPlotView` | 动画和粒子 |
| 音效 | 成功/失败/菜单有轻反馈 | 程序化短音 | 授权音频资产 |
| 空间 | 视觉水体、边界和碰撞一致 | `PlayerController` 数学判定 | 可视化 Collider/Trigger |

## 快照与评分流程

每次可试玩切片输出或手动截取：

1. `WorldHub_1080p_overview`：看家、森林、河、桥、游戏机是否一眼可读。
2. `WorldHub_bridge_and_river`：看水体、桥、河岸和碰撞是否一致。
3. `WorldHub_inventory_or_signboard`：看背包分类、木牌记录和短提示是否像生活工具。

评分用 `doc/visual_benchmark_review_stage8.md`。任一维度低于门槛时，不新增玩法，先修扣分项。
